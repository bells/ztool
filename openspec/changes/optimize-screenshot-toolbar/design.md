## Context

Zero Snap 的 macOS 自定义截图窗口由 `CaptureApp` 渲染全屏截图、标注 canvas、文本输入和工具栏。当前源码没有独立的截图选区状态，Rectangle 只是会写入最终图片的标注；复制和保存始终提交整张屏幕。`.capture-toolbar-live` 又通过 `left: 50%`、`bottom: 22px` 固定在视口底部，无法贴近用户期望的截图区域；按钮内容则直接写成英文字符串。工具栏操作本身已经集中在 `CaptureApp`，这些变化不需要修改 Rust 命令或 IPC 契约。验收同时暴露现有 macOS AppleScript 图片复制语法无法编译，以及 `.fullscreen(true)` 会让截图覆盖层表现为带系统窗口框架的原生全屏窗口，因此需要在不改变命令契约的前提下局部修复剪贴板传输和窗口创建方式。

本次设计先补齐真实截图选区，再把“选区决定工具栏位置”和“工具定义决定按钮语义”分别抽成可测试的前端边界。截图选区和标注矩形是不同概念，定位逻辑与最终裁剪都必须消费实际截图选区，不能把最近创建的矩形标注误当成截图选区。

## Goals / Non-Goals

**Goals:**

- 让工具栏始终靠近当前截图选区，并在选区贴近屏幕边缘或覆盖全屏时保持完整可见。
- 默认选择整张屏幕，允许用户通过 Select 工具拖拽创建真正的截图区域，并让复制、保存严格裁剪到该区域。
- 用一致的矢量图标替换工具栏中的可见英文，同时保留本地化名称、键盘可达性和清晰状态。
- 将定位决策抽成纯函数，覆盖不同视口、选区和工具栏尺寸，避免把边界判断散落在 React 与 CSS 中。
- 保持 Zero “calm, capable, compact”的产品风格，复用现有绿色选中/确认色和深色浮层。
- 保证图标化后的文字工具能稳定获得输入焦点，支持 Enter 输入多行内容，并通过鼠标左键点击编辑器外部完成标注。
- 在矩形工具后提供独立的椭圆标注工具，并复用既有的选择、历史与导出架构。
- 让 macOS 截图编辑器以无系统标题栏的无边框覆盖层出现，不触发原生全屏 Space 切换。

**Non-Goals:**

- 本次只支持通过 Select 重新拖拽选区；不增加选区移动、控制点缩放、窗口智能识别或多选区。
- 不改变标注绘制、命中测试、撤销重做历史、图片编码、复制、保存或钉图语义。
- 不新增颜色、线宽、字体、OCR、贴图或二级工具栏等能力。
- 不替换 Windows 的系统截图启动路径，也不扩大 Linux/其他平台支持范围。
- 不重构截图 Rust service、Tauri window 路由或 IPC 数据结构。

## Decisions

### 1. 以图片像素坐标保存唯一的截图选区

新增截图插件范围内的纯选区模型（建议 `captureSelectionModel.ts`）。`CaptureSelection` 使用与原始截图、标注 canvas 相同的图片像素坐标，初始值为 `{ x: 0, y: 0, width: session.width, height: session.height }`，因此整屏截图是明确状态而不是空值特例。

Select 工具在空白位置拖拽时创建新的截图选区；命中现有标注时仍保留原来的标注选择能力。选区拖拽过程中使用 draft，达到最小尺寸后才替换已提交选区，避免一次点击意外清空有效区域。Rectangle 继续只创建矩形标注，不能成为选区来源。

图片像素选区通过与现有 `pointerToImagePoint` 相同的 object-fit contain 几何映射到 CSS 视口矩形，用于绘制边框、尺寸徽标、选区外遮罩和工具栏锚点。映射逻辑抽成纯函数并覆盖 Retina/缩放比例、letterbox 偏移和全屏边界。

复制和保存先渲染原图与标注，再通过现有 `cropCanvasToPngDataUrl` 按截图选区裁剪。这样 Rust 仍接收同一个 PNG base64 字段，无需扩大 IPC。Pin 工具继续按用户为钉图拖出的局部 bounds 工作，不改其语义。

备选方案是把 Rectangle 标注兼作选区。该方案会把绿色边框写进最终截图、破坏多个矩形标注能力，也无法定义清晰的全屏默认值，因此不采用。

### 2. 使用纯定位模型计算工具栏的绝对视口坐标

新增截图插件范围内的纯函数（建议 `captureToolbarModel.ts`），输入包含：

- 当前截图选区的视口矩形；
- 实际测量的工具栏宽高；
- 当前视口宽高；
- 统一的边缘留白、选区间距和选区内缩进 token。

输出包含 `{ left, top, placement }`，其中 `placement` 至少区分 `outside-bottom`、`inside-bottom`、`outside-top` 和受限回退位置，供样式与测试观察。横向默认将工具栏右侧与选区右侧对齐，更接近截图确认动作发生的位置；最终 `left` 必须钳制在视口左右安全边距内。

垂直定位采用以下优先级：

1. 选区下方容得下工具栏和间距时，紧贴选区下边缘外侧。
2. 下方空间不足且选区内部高度足够时，放在选区底部内侧；全屏选区自然命中此规则。
3. 选区过矮、内部放置会遮住主要内容时，放到选区上方外侧。
4. 上下都无法完整容纳时，将工具栏钳制到视口安全区域，并保持所有操作可见。

选择用 TypeScript 纯函数而不是只依赖 CSS `bottom`、container query 或碰撞库：选区是自由移动的二维矩形，工具栏还需要按明确优先级在内外切换；纯函数更容易验证，也无需为单个浮层引入通用定位框架。

### 3. 从实际 DOM 尺寸和截图选区状态驱动重新定位

`CaptureApp` 使用工具栏 ref 和 `ResizeObserver` 获取真实尺寸，在截图选区改变、视口 resize、语言/图标布局改变时重新计算。首次尚未测得尺寸时工具栏保持不可交互的预布局状态或使用稳定的保守尺寸，测量完成后一次定位，不在屏幕底部短暂闪现。

工具栏使用截图窗口内的绝对定位坐标，不再通过 `left: 50%` 和固定 `bottom` 居中。定位样式仅负责应用模型结果；间距常量进入截图工具栏 token，避免 JSX、CSS 和测试各自维护魔法数字。

备选方案是根据每个按钮数量预估固定宽度。该方案在系统字体缩放、未来新增动作或不同图标尺寸时容易漂移，因此不采用。

### 4. 采用 `lucide-react` 提供统一的线性 SVG 图标

为选择、矩形、箭头、画笔、文字、马赛克、钉图、撤销、重做、删除、取消、保存和复制/确认选择语义最接近的 Lucide 图标。`lucide-react` 维护活跃、使用广泛且支持按图标导入和 `currentColor`，可以保持一致的线宽与光学尺寸，同时避免复制第三方 SVG 或自绘一套难以维护的路径。

图标只负责视觉表达；工具描述仍保留稳定的 `CaptureTool` 值、本地化 label key 和 action handler。按钮渲染由一份显式、强类型的描述数据驱动，不使用 `any`，也不通过图标名称动态查找组件。

备选方案包括 Unicode 字符和项目内手写 SVG。Unicode 在不同系统字体上的字形、基线和粗细不一致；手写 SVG 会增加风格一致性与后续维护成本，因此均不采用。

### 5. 纯图形按钮保留完整语义与状态反馈

每个按钮至少提供本地化 `aria-label` 和 tooltip（原生 `title` 或项目统一 tooltip 组件）。工具按钮通过 `aria-pressed` 表达当前选中工具；禁用态继续使用原生 `disabled`；危险动作、取消、保存和复制保留现有颜色层级，但不依赖颜色作为唯一含义。

按钮的可点击区域维持至少 44×44 CSS 像素，图标采用统一的 18–20px 光学尺寸。键盘 Tab 顺序跟随视觉顺序，现有 Escape、Delete/Backspace、撤销和重做快捷键继续有效；可见 focus ring 不被浮层背景吞没。工具栏按“标注工具 / 历史与删除 / 完成动作”分组，并用低对比分隔符表达结构。

### 6. 保持截图平台和数据边界不变，并修复 macOS 剪贴板传输

选区、定位和图标变化发生在 React 截图窗口和 CSS。`CaptureSession`、`commit_screenshot`、`pin_screenshot`、`cancel_screenshot_session` 的字段与调用方式不变，因此 Rust 和 TypeScript IPC 无需同步修改。验收发现 `copy_png_to_clipboard` 使用的 AppleScript `PNG picture` 表达式在当前 macOS 无法编译；该局部实现改为通过项目现有 Cocoa/Objective-C 依赖直接向 `NSPasteboard` 写入 `public.png` 数据，避免临时文件、脚本语法和路径转义问题。Windows 继续走 `ms-screenclip:`/Snipping Tool，只有使用 Zero 自定义编辑窗口的平台获得新工具栏和原生复制修复。

### 7. 使用多行编辑器和点击外部完成文字标注

文字工具点击画布时不再调用 canvas 的 pointer capture；动态 `textarea` 挂载后在下一动画帧显式聚焦并把光标放在文本末尾，避免 WebKit 在同一 `pointerdown`/`pointerup` 序列中把焦点抢回 canvas，导致空输入框立即 blur。Enter 保留浏览器原生行为并插入换行，不承担完成动作；用户用鼠标左键点击输入框外部时，通过 blur 或 canvas 指针入口提交当前草稿，Escape 仍取消。用 ref 同步保存最新草稿，避免 blur 与 pointer 事件顺序造成重复提交或丢失最后一次输入。

文字标注继续保存为单个字符串，其中换行以 `\n` 表示。渲染和命中边界按行拆分：第一行沿原基线绘制，后续行使用统一行高递增，宽度取最长行的估算宽度，高度覆盖全部行。最终 Copy/Save 仍走同一 canvas 渲染和裁剪链路。

### 8. 将椭圆作为独立的类型化标注

`CaptureTool` 与 `AnnotationObject` 分别增加 `ellipse` 工具和值类型，使用与矩形一致的归一化外接矩形记录 `{ x, y, width, height }`，但通过 canvas `ellipse` 路径绘制。椭圆按钮固定排在 Rectangle 后、Arrow 前；命中、撤销重做、删除和导出复用现有标注分发，不把椭圆与截图选区或矩形标注混用。

### 9. 使用无边框显示器覆盖窗口代替 macOS 原生全屏

截图窗口继续由 Rust/Tauri 动态创建，但移除 `.fullscreen(true)` 和可见标题文本。窗口以 `decorations(false)`、`visible(false)` 创建，先读取主显示器的物理位置与尺寸，通过 `set_position` 和 `set_size` 精确铺满显示器，再显示并聚焦。这样窗口从首次可见帧开始就是截图覆盖层，不经历 macOS 原生全屏切换，也不会短暂暴露标题栏。

窗口定位、调整、显示或聚焦任一步失败时关闭尚未准备好的覆盖窗口并返回错误，让既有会话清理和原窗口恢复逻辑接管。备选方案是保留 `.fullscreen(true)` 并继续叠加标题栏样式；该方案仍受 macOS 原生全屏窗口生命周期控制，不能稳定满足微信截图式的无窗口框架体验，因此不采用。

## Risks / Trade-offs

- [Risk] 工具栏首次测量或窗口缩放时出现跳动 → 使用预布局/隐藏状态、`ResizeObserver` 和同一帧布局更新，避免先渲染到旧的固定底部位置。
- [Risk] object-fit contain 与 Retina 图片像素比例混用导致选区框或裁剪偏移 → 统一从一个纯映射模型产生指针反算和视口正算，测试非 1:1 比例与 letterbox 偏移。
- [Risk] Select 工具同时承担标注选择和重建截图选区，点击语义冲突 → 优先命中已存在标注；仅在空白处开始选区 drag，并用 draft 最小尺寸保护已有选区。
- [Risk] 选区比工具栏更窄或更矮，常规内外位置都不理想 → 横向以视口安全边距钳制；垂直按外下、内下、外上、视口回退的确定顺序选择，优先保证工具完整可用。
- [Risk] 工具栏覆盖选区底部内容 → 只有外部空间不足且选区高度足够时才放入内部，并使用固定内缩；用户仍可移动或调整选区触发重新定位。
- [Risk] 图标含义对首次使用者不够明确 → 始终提供本地化 tooltip、可访问名称和明显选中态，不删除现有快捷键语义。
- [Risk] 新图标依赖增加包体 → 只使用 ESM 命名导入并通过生产构建检查 tree-shaking，不引入完整图标字体或运行时注册表。
- [Risk] macOS 原生剪贴板调用只在真实 AppKit 环境可用 → 使用独立命名 pasteboard 做 PNG 字节回归测试，并保留真实 Copy 验收项；测试不覆盖用户系统剪贴板。
- [Risk] 动态文字输入框在 WebKit 指针结束阶段丢失焦点，或点击外部时 blur 与 pointer 事件重复提交 → 延后一帧显式聚焦、避免文字工具捕获 canvas 指针，并用同步 ref 和源码回归覆盖提交顺序。
- [Risk] 多行文字的 DOM 行高与 canvas 绘制基线不一致 → 使用共享字体大小和确定的 1.35 行高计算渲染及命中高度，并在真实窗口核对 Copy/Save 结果。
- [Risk] 物理显示器边界与 WebView 逻辑像素在 Retina 下比例不同 → 使用 Tauri 的 `PhysicalPosition`/`PhysicalSize` 设置原生窗口，由既有图片到视口映射处理 WebView 内缩放，并保留 Retina 实机验收。
- [Risk] 浏览器测试通过但 Tauri 全屏窗口坐标、Retina 缩放或多显示器边界仍有偏差 → 将真实 macOS 截图窗口、多种边缘选区和全屏选区列为完成前人工验证项，不用源码测试替代运行时结论。

## Migration Plan

1. 先增加选区/坐标映射和纯定位模型的边界测试，再接入真实选区与裁剪提交。
2. 把 `CaptureApp` 的工具栏改为测量并消费真实选区的视口结果。
3. 引入 `lucide-react`，建立强类型工具/动作描述，替换可见英文内容并补齐本地化名称。
4. 收敛截图选区与工具栏 CSS，验证选中、hover、focus、active、disabled、danger 和 confirm 状态。
5. 运行前端单元测试、生产构建、OpenSpec 严格校验与真实 Tauri macOS 截图窗口检查。

回滚时可恢复旧的文本描述与固定底部 CSS；Rust 服务、持久化数据和 IPC 均未迁移，不需要数据回滚。

## Open Questions

- 无。图标具体映射可在实现阶段按 Lucide 实际可用名称做等价选择，但不得改变本规范定义的操作集合与语义。

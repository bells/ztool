## Why

Zero Snap 当前将编辑工具栏固定在屏幕底部，工具栏与截图选区可能相距很远，尤其在大屏幕或较小选区下会打断连续操作。工具按钮同时依赖英文短标签，识别速度、界面紧凑度和中英文一致性都弱于 iShot、微信截图等成熟截图工具。

## What Changes

- 让截图编辑工具栏跟随当前截图选区定位，默认紧贴选区下边缘，并在屏幕边缘内自动钳制。
- 当选区下方空间不足（包括截取整个屏幕）时，将工具栏放入选区底部，避免工具栏离开可视区域或与选区相距过远。
- 为当前仅有全屏画布的 macOS 自定义编辑器补充真实截图选区：默认选择整屏，用户可通过 Select 工具拖拽重建选区，复制和保存只提交选区内容。
- 将 Select、Rect、Arrow、Pen、Text、Mosaic、Pin、Undo、Redo、Delete、Cancel、Save 和 Copy 等可见英文按钮替换为语义清晰、风格一致的图形图标。
- 为图标按钮保留本地化 tooltip、可访问名称、键盘操作、选中态、危险态、确认态和禁用态，使纯图形界面仍然可发现、可理解。
- 为选区映射、工具栏定位规则和工具描述数据增加可独立测试的前端模型及边界用例，不改变现有撤销重做、标注渲染和平台启动路径。
- 将 macOS 图片复制从无法编译的 AppleScript `PNG picture` 脚本改为原生 `NSPasteboard` PNG 数据写入，保持现有提交命令和数据契约不变。
- 修复文字工具输入框被 canvas 指针序列立即抢回焦点的问题；文字编辑器支持 Enter 换行，并在用户用鼠标左键点击输入框外部时完成标注。
- 在矩形工具后新增椭圆工具，复用现有标注历史、选择、渲染和裁剪导出链路。
- 参照微信截图，将 macOS 截图编辑器改为按显示器物理边界铺满的无边框覆盖窗口，不再进入可能暴露系统标题栏的原生全屏模式。

## Capabilities

### New Capabilities

- `screenshot-toolbar`: 定义 Zero Snap 的真实截图选区与裁剪提交、编辑工具栏相对选区的自适应定位、图形化操作入口、状态反馈和可访问行为。

## Impact

- 主要影响 `src/plugins/screenshot/capture/` 下的截图编辑 React 组件、选区/工具描述、文字与椭圆标注模型及新增的纯模型，以及 `src/App.css` 中的截图浮层样式。
- 增加对应的 Node 单元测试，覆盖选区创建与图片/视口坐标映射、选区裁剪、工具栏外置、内置、横向钳制、小视口和全屏选区等情况。
- 不新增 Rust command 或 IPC 字段；前端引入维护活跃、可按图标 tree-shake 的 `lucide-react`，避免自行维护一套截图工具 SVG；macOS Rust 服务局部修复剪贴板传输和截图覆盖窗口创建方式。
- macOS 自定义编辑器行为发生变化，Windows 系统截图启动路径和其他平台错误处理保持不变。
- 需要在真实 Tauri 无边框截图覆盖窗口中人工验证无系统标题栏/原生全屏 Space 切换、不同屏幕尺寸、边缘选区、全屏选区、缩放显示、图标 tooltip 和键盘交互。
